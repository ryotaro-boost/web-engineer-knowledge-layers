渡されたコードを `_anti-patterns/` 索引と全件照合し、該当するアンチパターンを列挙してください。

## 入力
$ARGUMENTS（コードブロック または プロジェクト内のファイルパス）

例:
- `\`\`\`python\n...\n\`\`\``
- `src/api/users.ts`
- `Dockerfile`

## 手順

1. 入力からコードを取得する（ファイルパスが渡されたら `Read` で読む）
2. コードの言語・用途・依存ライブラリから、関連レイヤーを推定する（複数該当しうる）
3. `_anti-patterns/_index.md` を読み、レイヤー別 / パターン別の索引を把握する
4. 関連レイヤーの `_anti-patterns/レイヤー別/Layer{N}.md` を読み、各アンチパターン項目とコードを照合する
5. パターン別ファイル（過剰なフォールバック / 防御的すぎるエラーハンドリング / 不要な抽象化 / 既存ユーティリティの再発明）も全件照合する（パターン別ファイルが未作成の場合は `_anti-patterns/_index.md` の説明文を使う）
6. 該当したアンチパターンを **重要度順** で報告する

- 用途: ...

## 該当しなかった主要観点

スキャン対象外のレイヤーや、該当しなかったが学習者が留意すべき観点を簡潔に挙げる:
- Layer X: 該当なし
- パターン Y: 該当なし

## 横断的レビュー（_anti-patterns/_index.md より）

1. プロジェクトの規約・既存パターンに従っているか: ✅ / ❌（理由）
2. 「起こりえないエラーへの対処」を書いていないか: ✅ / ❌（理由）
3. 要求された機能を「最小限」で実現しているか: ✅ / ❌（理由）

## 推奨アクション

- 重要度 🔴 / 🟠 のアンチパターンを優先して修正する
- 該当する追プロンプトの雛形:

\`\`\`
（修正のためのプロンプト雛形）
\`\`\`

- より詳細なトピック観点でのレビューが必要なら `/review-ai-code <トピック名>` を使う

## 重要度の判定基準

| 重要度 | 基準 |
|---|---|
| 🔴 Critical | セキュリティ脆弱性、データ消失リスク、本番停止につながる（例: TLS検証無効化、シークレット直書き、リトライ無限ループ） |
| 🟠 High | 本番運用で必ず障害になる（例: タイムアウトなし、再接続なし、`Cache-Control` 未設定、エラーを200で返す） |
| 🟡 Medium | パフォーマンス・運用効率に影響（例: コネクション使い回しなし、CNAMEチェーン、ロギング過剰） |
| 🔵 Low | スタイル・一貫性の問題（例: 命名規則の逸脱、コメント不足） |

## スキャンの設計指針

### 全件照合 vs トピック観点

| skill | 役割 |
|---|---|
| `/anti-pattern-scan`（このskill） | レイヤーをまたいで **横断的に** 検出。パターン別索引を含めて全件照合 |
| `/review-ai-code` | **特定トピックに絞った** 深いレビュー。誤解されやすいポイント・効くプロンプトの型まで踏み込む |

両方を組み合わせると効果的。スキャンで横断的に当たりをつけ、深掘りしたいトピックを `/review-ai-code` でレビューする。

### 関連レイヤー推定の基準

- Dockerfile / Docker Compose → Layer 1
- HTTP クライアント / サーバー / API ハンドラ → Layer 2 (HTTP/HTTPS, TCP/IP) + Layer 4
- Terraform / DNS レコード → Layer 1 + Layer 2
- Nginx / TLS 設定 → Layer 2 (TLS/SSL)
- WebSocket → Layer 2 (WebSocket)
- DB クエリ / トランザクション → Layer 3
- 認証・認可・JWT → Layer 6
- React / Vue / フロントエンド → Layer 4 (Frontend)

### 対象外の指摘は控える

- 教材外の領域（ビジネスロジックの正しさ、ドメインモデルの妥当性）には踏み込まない
- スタイル（インデント・命名）は Low か対象外
- マイクロ最適化（プロファイリングなしの推測）は出さない

## 注意事項

- 検出したアンチパターンは **必ず索引（`_anti-patterns/レイヤー別/Layer{N}.md`）への `[[]]` リンクで出典を明示** する
- 索引が未作成のレイヤー（整備中）は `_anti-patterns/_index.md` の整備状況を見て「該当する可能性あり」とのみ報告する
- ハルシネーション禁止: コードに書かれていない動作を仮定しない
- セキュリティ上の問題は最優先で報告

### 教材設計上の注意

本教材の対象は **初学者〜ミドル層エンジニアをシニア層へ押し上げる**:

- アンチパターン名・トピック名・横断パターン名はすべて [[]] リンクで案内する
- 「なぜこれがアンチパターンか」を **理由とセットで** 提示する（パターン名だけ列挙しない）
- 修正方針は **動かせる粒度** で提示する（「適切に修正してください」では弱い）
- 重要度の判定理由を一言添える — 学習者が次回から自分で重要度判断できるように
