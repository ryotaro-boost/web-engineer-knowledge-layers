実務の症状を渡されたら、関連するレイヤー・トピックへの追跡経路を案内してください。

## 入力
$ARGUMENTS（症状の自然言語説明、例: `APIが遅い` / `本番でメモリ使用量が上昇し続ける` / `ログインしても5分で切れる`）

## 手順

1. 入力された症状から、想定される現象（高レイテンシ / メモリリーク / 認証切れ / データ不整合 等）を特定する
2. 関連する可能性のあるレイヤーを **上位（症状に近い）から下位（原因に近い）の順** で列挙する
   - 例: 「APIが遅い」→ Layer 4 (App) → Layer 5 (Performance) → Layer 3 (DB) → Layer 2 (Network) → Layer 1 (OS)
3. 各レイヤーで疑うべきトピックを `Glob` で確認しながら、関連 `[[]]` リンクを示す
4. 各トピックで実際に確認すべき項目（コマンド・ヘッダ・ログ・メトリクス）を提示する
5. レビュー手順を「**観察 → 仮説 → 検証**」の順で案内する

## 仮説検証の流れ

1. **観察** — 上記の「観察すべき指標」を実環境で取得
2. **仮説** — どのレイヤーが最も怪しいか3つ挙げる
3. **検証** — 各仮説について「もしこれが原因なら、どんなデータが見えるはず」を確認
4. **絞り込み** — 検証結果に応じて他レイヤーへ降りる / 上る

## 追跡経路の設計指針

### 上位 → 下位の原則

症状はユーザーやアプリケーションに近い層で観察されるが、原因は下位レイヤーにあることが多い。**上位から降りる**ことで以下のメリットがある:

- 観察コストが低い指標から順に確認できる（メトリクス → ログ → カーネル）
- 早期に「原因はここではない」と除外できると、次のレイヤーに集中できる
- 同じ症状に複数原因が重なっている場合、優先度を判断できる

### 各レイヤーで提示すべき内容

| 内容 | 説明 |
|---|---|
| 関連トピック | `[[]]` リンク。本教材の該当トピックを必ず引用する |
| 確認方法 | 具体的なコマンド・ヘッダ・メトリクス名 |
| 「これが見えたら次の層」の判断 | 何が観察できれば次のレイヤーに降りるべきかの基準 |

### 典型的な追跡経路の例

| 症状 | 経路 |
|---|---|
| APIが遅い | Layer 4 → Layer 5 → Layer 3 (DB) → Layer 2 (HTTP/TCP) → Layer 1 (CPU/IO) |
| メモリ使用量が増え続ける | Layer 4 → Layer 1 (メモリ管理) → Layer 0 (データ構造) |
| 5xxが急増 | Layer 4 → Layer 5 → Layer 3 → Layer 2 (TLS/DNS) → Layer 1 (Docker/OS) |
| ログイン切れ | Layer 6 (認証) → Layer 4 (Cookie/Session) → Layer 2 (TLS/HTTPS) |
| 本番でだけ動かない | Layer 1 (Docker/環境) → Layer 2 (DNS/TLS) → Layer 6 (権限) |
| データ不整合 | Layer 3 (トランザクション) → Layer 4 (並行性) → Layer 0 (並行性の基本) |

## 注意事項

- 関連トピックは `Glob` で実在を確認してから `[[]]` で示す（リンク切れを起こさない）
- 「とりあえず全レイヤーを列挙する」のではなく、症状から直接関連する3〜4レイヤーに絞る
- 各レイヤーで2〜4トピックを案内する（多すぎると追跡が散漫になる）
- 「すぐに本番で実行できる」コマンドを提示する（pseudo コードでなく実コマンド）
- 仮説の優先度を必ず提示する（「まずどこを疑うか」）

### 教材設計上の注意

本教材の対象は **初学者〜ミドル層エンジニアをシニア層へ押し上げる**。診断ガイドもこの設計に沿わせる:

- **コマンドの意図を一行で説明する** — 「`ss -tan state time-wait | wc -l`（TIME_WAIT 状態の TCP 接続数を数える。ポート枯渇の兆候）」
- **「これが正常 / これが異常」の閾値を可能な限り示す** — 「p99 が SLA を超えていれば異常」「TIME_WAIT が数千を超えると要警戒」
- **症状→原因の思考プロセスを言語化する** — 「なぜこのレイヤーから疑うか」「次に降りる判断基準は何か」
- **既知前提の言い回し（「言うまでもなく」「自明だが」）を避ける**
- 学習者が **次回からこのパターンで自分で追跡できる** ことを目指す
