`_glossary/用語集.md` への用語追加・更新を行ってください。本教材は **初学者〜ミドル層エンジニアをシニア層へ押し上げる** 読み物として設計されており、用語集は「教材を読んでいて詰まったときの最低限辞書」として機能する必要があります。

## 入力

$ARGUMENTS

形式:
- 用語名のみ（例: `WebSocket`） → 用語追加
- 用語名 + 一言の説明（例: `SLA サービスレベル契約`） → ヒント付き追加
- `--review` → 用語集の整合性チェック（リンク切れ・カテゴリ過不足）

## 手順

### A. 用語追加の場合

1. `_glossary/用語集.md` を読み、既存エントリを把握
2. 該当用語が既に存在するか確認 — 既存なら更新提案、なければ新規追加
3. 用語が属するカテゴリを判定（HTTPと通信 / 認証・認可 / データベース / 並行性 / 計算量 / 設計 / 運用 / AI協働、または新カテゴリ）
4. 用語の **3点セット** を作成:
   - **1行定義** — 1文で核心を表す
   - **もう一歩** — なぜその概念が必要か、典型的な誤解、代表的な実例（2〜4行）
   - **関連** — 教材内のトピックへの `[[]]` リンク（Glob で実在確認）
5. 関連するトピックドキュメントを `Grep` で検索し、その用語が初出する箇所を確認
6. 用語集に追記する（カテゴリ索引の表 + 該当カテゴリ section）
7. 追加した用語が出てくる主要トピックに、`> [!info] 用語ミニ辞典` Callout で簡易補足を入れる提案をユーザに行う（自動修正はしない）

### B. `--review` の場合

1. `_glossary/用語集.md` の全エントリを読む
2. 各 `[[]]` リンクを Glob で実在確認 → リンク切れがあれば報告
3. カテゴリ索引の表と本文の見出し数の整合を確認
4. 各エントリが **1行定義 / もう一歩 / 関連** の3点を全て持っているか確認
5. 教材内で頻出するが用語集に未掲載の用語を `Grep` で検出して候補として報告

## 出力フォーマット

### A. 追加の場合

```
## 追加対象
- 用語名: <name>
- カテゴリ: <category>
- 既存有無: 新規 / 更新

## 追記する内容（プレビュー）

### <用語名>
**1行定義:** ...
**もう一歩:** ...
**関連:** [[トピック1]] / [[トピック2]]

## 関連トピックでの初出箇所

- [[Layer{N}-XXX/トピック名]] の {{セクション}} 行 — ここに `> [!info] 用語ミニ辞典` 挿入を推奨
- ...

## 確認後、ユーザの承認で用語集に書き込みます。
```

### B. `--review` の場合

```
## 用語集レビュー

### リンク切れ
- [[XXX]] (用語: YYY) — 実在しない

### 3点セット欠落
- ZZZ — 「もう一歩」が空

### 未掲載候補（教材内で頻出）
- AAA — N トピックで使用、未掲載
- BBB — N トピックで使用、未掲載

### 整合性
- カテゴリ索引と本文見出しの数が一致: ✅ / ❌
```

## 用語集への記述スタイル

各エントリは以下のフォーマットで統一する:

```markdown
### 用語名 (英語名 / 別名)
**1行定義:** （1文で核心）。
**もう一歩:** （2〜4行で「なぜ必要か」「典型的な誤解」「代表的な実例」を書く。専門用語は控えめに）。
**関連:** [[トピック1]] / [[トピック2]]
```

**書き方の原則:**

- 「1行定義」は **30字程度を目安** に短く核心を捉える。読み飛ばし用
- 「もう一歩」は **「なぜ気になるか」「混同しやすい何と何か」** を含める
- **関連トピック** は教材内に **実在する** ものに限定（Glob で確認）
- 既存トピックがない用語は、関連レイヤーへのリンクで代替

## 教材設計上の注意

本教材の対象は **初学者〜ミドル層エンジニアをシニア層へ押し上げる**:

- 用語の説明には **「なぜそれが概念として必要か」** を含める。定義だけ並べると「知ってるつもり」を量産する
- **「○○と混同されやすい」** を意識的に書く（認証 ⇔ 認可、ステートレス ⇔ 冪等、楽観 ⇔ 悲観など）
- カタカナ語と英語両方を併記 — 検索性向上と原文記事を読むための足がかり
- **詰まる用語を放置しない** が用語集の存在意義。難しい用語をさらに難しい用語で説明しない

## 注意事項

- `_glossary/用語集.md` のカテゴリ索引（表）と本文見出しを **必ず両方更新** する
- カテゴリが既存にないときは **「新カテゴリを作るか、既存にぶら下げるか」をユーザに確認**
- 同じ用語が異なる文脈で違う意味を持つ場合は、文脈別に分けて記述
- ユーザの承認を得てから `_glossary/用語集.md` を編集する
- 用語ミニ辞典 Callout のトピックへの挿入は **自動編集しない**（提案のみ、ユーザが採否判断）
