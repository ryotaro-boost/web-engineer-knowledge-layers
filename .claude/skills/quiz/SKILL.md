指定されたトピックまたはレイヤーから、理解度クイズを動的に生成してください。

## 入力
$ARGUMENTS（形式: `トピック名` / `LayerN` / `LayerN: トピック名` / `LayerN: 横断` のいずれか）

例:
- `Docker`
- `Layer2`
- `Layer2: 横断` （Layer2 全トピック横断）
- `Layer4: HTTP-HTTPS`

## 手順

1. 入力からトピックまたはレイヤーを特定する
   - トピック名の場合: `Glob` で該当ファイルを探す（例: `**/Docker.md`）
   - レイヤーの場合: `Layer{N}-*/_index.md` を読み、トピック一覧を取得する
2. 対象トピックの以下セクションを読む:
   - `3分で全体像 → これだけは覚える3つ`
   - `誤解されやすいポイント`
   - `設計のベストプラクティス`
   - `AIエージェントとの協働 → AI生成コードのレビュー観点 / AI実装のアンチパターン`
   - `理解度セルフチェック`（既存の解答指針を参考にしつつ、設問は重複させない）
3. 以下の出題ルールで5問を生成する:
   - **問1-2: 理解確認** — トピックの核（「これだけは覚える3つ」「誤解されやすいポイント」）から
   - **問3-4: AI生成コードレビュー設問**（必須2問）— 該当トピックのアンチパターン表からコードサンプルを構成し、「何が問題か」を問う
   - **問5: 応用・横断** — 関連レイヤーとの接続、症状からの逆引き、設計判断
4. 各問にObsidian Callout 形式で解答の指針を添える（`> [!note]- 解答の指針`）
5. 専門用語が出る問題には `> [!info] 用語ミニ辞典` Callout を冒頭に添える

## 出題ルールの詳細

### AI生成コードレビュー設問（問3-4）の作り方

- 対象トピックの「AI実装のアンチパターン」表から1〜2個を組み合わせてコードサンプルを構成する
- コードは **15〜30行程度の実用的なもの** にする（短すぎると問題が見えない、長すぎると論点がぼやける）
- 言語は対象トピックで主流のもの（Web API なら TypeScript / Python、インフラなら Bash / Dockerfile / Terraform）
- アンチパターンは複数（2〜4個）を意図的に混入する
- 解答指針では各アンチパターンを順に挙げ、それぞれ「なぜ問題か」「どう直すか」「修正版コード」を示す

### 応用・横断問題（問5）の作り方

- 「症状から原因」型: 「APIが遅い場合、このトピックの観点で何を疑うか」
- 「トレードオフ」型: 「Aを選ぶかBを選ぶかの判断基準は」
- 「他レイヤー接続」型: 「このトピックは Layer X とどう関係するか」

## 教材設計上の注意

### 初学者フレンドリーであること

本教材の対象は **初学者〜ミドル層エンジニアをシニア層へ押し上げる** ことを目的とする読み物。クイズもこの設計に沿わせる:

- **設問本文では難語・略語を初出時に説明する**（または用語ミニ辞典に入れる）
- **解答指針は「結論だけ」で終わらせない** — 「なぜそうなるか」の思考プロセスを必ず示す
- **「自明」「言うまでもなく」のような既知前提の言い回しを避ける**
- 解答指針内のコード例は **動かせる最小構成** にする（疑似コードで済ませない）
- 1問あたりの解答指針は 5〜15行程度を目安に。重要な問題（特にAIレビュー）は厚く

### やらないこと

- 既存の「理解度セルフチェック」と同じ設問を出さない（必ず新規）
- 出題対象外のトピックへの言及（横断問題で関連トピックに触れる場合は `[[]]` リンクで案内する）
- 解答を自動採点・スコアリングしない（学習者が自分で読み込むのが目的）
- ハルシネーションを避けるため、本文に書かれていない事実を加えない

## 注意事項

- 出題前に必ず該当トピックの本文を読み、設問の答えがファイル内で確認できる状態にする
- AI生成コードレビュー設問のコードサンプルは、実在するライブラリ・関数を使う（架空 API は禁止）
- 関連トピック（`prerequisites` / `next_steps`）への横断はリンク `[[]]` で案内する
