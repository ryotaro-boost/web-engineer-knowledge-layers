渡されたAI生成コードを、関連するトピックの観点でレビューしてください。

## 入力
$ARGUMENTS（形式: `トピック名 + コード` または `コードのみ`）

例:
- `認証と認可\n\`\`\`typescript\n...\n\`\`\``
- コードブロックのみ（トピック未指定）

## 手順

1. 入力からコードを抽出し、トピック名が指定されていれば該当トピックを特定する
2. トピックが指定されていない場合は、コードの内容（言語・使用ライブラリ・処理内容）から関連トピックを推定する
3. 関連トピックの以下セクションを読む:
   - `誤解されやすいポイント`
   - `設計のベストプラクティス`
   - `AIエージェントとの協働 → AI生成コードのレビュー観点`
   - `AIエージェントとの協働 → AI実装のアンチパターン`
4. `_anti-patterns/_index.md` の横断的レビュー観点 + パターン別アンチパターンを参照する
5. 以下のフォーマットで報告する

## 報告フォーマット

```
## レビュー対象
- 関連トピック: [[XXX]]
- 主要言語: ...
- 主要処理: ...

## 良い点
- （正しく実装されている箇所、トピックの観点でクリアできている点）

## 問題点

### 1. （簡潔なタイトル）
- **観点:** （レビュー観点のどれに該当するか: ハルシネーション / アンチパターン / セキュリティ / 要件適合性 / etc）
- **何が問題か:** ...
- **どう直すか:** ...
- **追プロンプト案:**
  ```
  （AIに直させるためのプロンプト雛形）
  ```

### 2. ...

## 横断的アンチパターン照合
- 過剰なフォールバック: 該当 / 該当なし
- 既存ユーティリティの再発明: 該当 / 該当なし
- 不要な抽象化: 該当 / 該当なし
- 防御的すぎるエラーハンドリング: 該当 / 該当なし

## 総評
- （優先度: critical / high / medium / low）
- （学習者へのコメント: 何を学ぶ機会になるか）
```

## レビューの重点

### 必ず見るべき観点
1. **ハルシネーション:** import / 関数 / 引数 / 設定キーが実在するか（推定で構わないが、明らかに架空のものは指摘）
2. **セキュリティ:** トピックがLayer 6関連でなくても、認証・認可・入力検証・SQL/コマンドインジェクション・秘密情報の扱いを必ず検閲
3. **過剰なフォールバック:** 「起こりえないケース」への try/catch やデフォルト値
4. **既存ユーティリティの再発明:** プロジェクト規約・標準ライブラリで提供されている処理を自前実装していないか
5. **要件不足:** トピックの「これだけは覚える3つ」が実装に反映されているか

### 軽微な指摘は控える
- スタイル（インデント・命名規則）の好み
- マイクロ最適化（プロファイリングなしの推測）
- 教材的な意図的簡略化

## 注意事項

- ハルシネーション禁止: コードに書かれていない動作を仮定しない
- セキュリティ・パフォーマンス・データ整合性に関わる問題は最優先で報告する
- 学習者が「なぜこれが問題か」を言語化できるよう、観点と理由を必ず明示する
- **AI生成コードを丸呑みする習慣を学習者が身につけるのを防ぐのが目的**
- 関連トピックが複数ある場合は、最も影響度の高いもの1-2個に絞って引用する
- 修正は提案にとどめ、自動では行わない
