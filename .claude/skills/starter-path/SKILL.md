学習者の状況に応じて、最小学習パスと週次プランをパーソナライズしてください。

## 入力

$ARGUMENTS（自然言語で学習者の状況。例: `5年 Java、フロントは初めて` / `新卒1年目、HTTPは知ってる` / `バックエンド志望でセキュリティが弱い`）

入力が不足している場合は `AskUserQuestion` で以下を確認:

| 質問項目 | 確認したい情報 |
|---|---|
| 経験年数 | 0年（学生）/ 1-3年 / 3-5年 / 5年以上 |
| メインのロール | バックエンド / フロントエンド / フルスタック / SRE / 学習中 |
| 既に分かっているトピック | HTTP / RDB / 認証 / 並行性 / コンテナ など |
| 苦手意識 | 並行性 / セキュリティ / DB / フロント / インフラ など |
| 学習に使える時間 | 週X時間 / 平日中心 / 週末中心 |

## 手順

1. 入力 + 必要なら追質問で学習者プロファイルを確定
2. `_starter/00_最小学習パス.md` の 14トピックを読む
3. `_starter/01_週次プラン.md` の 4週構成を読む
4. プロファイルに応じて以下を決定:
   - **スキップしてよいトピック** （既知、または役割上不要）
   - **深掘りすべきトピック** （志望ロールに直結 / 苦手意識あり）
   - **追加すべきトピック** （14トピック外だが、その人に必要）
   - **週の延長 / 短縮** （学習時間に応じて）
5. パーソナライズした **「あなた専用の最小学習パス + 週次プラン」** を提示
6. プランの **想定外コスト** （トピックを増やしたぶん時間が伸びる等）を明示

- 最小学習パスの14トピックは **「3分で全体像」のみ全件拾う**で1日完結
- AI協働章とセルフチェック3問目（AI生成コードレビュー設問）に集中

## パーソナライズの判断指針

### 「スキップさせてよい」基準

- 既知のトピックを「もう知っている」と申告された
- ロール上、3年以内には実務で触らない可能性が高い
- ただし **AI協働章とセルフチェック3問目だけは全員に推奨**（AIレビュー力は全員必要）

### 「深掘りさせる」基準

- 志望ロールに直結
- 苦手意識を申告された
- 実務で頻繁に詰まると申告された

### 「14トピック外を追加する」基準

- 志望ロールで必須なのに14トピックに含まれない
- 例: フロントエンド志望なら [[アクセシビリティ]]、SRE志望なら [[ロードバランシング]]

### 「週を延長する」基準

- 経験 0-1 年で本教材が初の体系学習
- 週次学習時間が 2 時間未満
- 用語集を頻繁に引かないと進めない場合（用語不足）

## 注意事項

- 14トピックは **「最低限を揃える」** 設計のため、**スキップさせすぎない**（特に [[認証と認可]] [[SQLインジェクション]] [[CSRF]] は全ロール必須）
- 既知トピックも **再読の価値はある**（数ヶ月後に違う層が見える）— スキップではなく「3分で全体像のみ」を提案
- 「これだけ覚える3つ」とセルフチェックは **全員に推奨**
- 学習者の自己申告に依存するため、プロファイルが過大評価された場合に備え **「本文を読んで難しいと感じたら基本パスに戻る」**を最後に必ず添える
- AskUserQuestion を使う際は質問を **3つ以下** に絞る（多いと回答が雑になる）

## 教材設計上の注意

本教材は **じっくり何度も読み込むことで効果がある読み物**:

- パスを「最短で完了させる」ことを目的化させない
- 4週間で14トピックを「読み終える」より、**「再読の動機を作る」** ことを優先
- セルフチェック3問目（AI生成コードレビュー設問）が **本教材の核**。これに答えられないなら本文に戻るプランを必ず提示
- パーソナライズ後も **[[_starter/02_実務症状からの逆引き]]** への動線を残す（読み終わった後の使い道）
