指定されたレイヤーとトピック名に基づいて、学習ドキュメントを作成してください。

## 入力
$ARGUMENTS（形式: `LayerN トピック名`、例: `Layer0 データ構造とアルゴリズム`）

## 手順

1. `_templates/topic-template.md` を読み、テンプレート構造を確認する
2. `web-engineer-knowledge-layers.md` から該当トピックの記述を抽出し、文脈を把握する
3. Glob で関連する既存トピック・details の実在を確認し、`[[]]` リンクが切れないようにする
4. テンプレートに従い、以下を含むトピックドキュメントを作成する

### フロントマター（全項目必須）

- `layer`: N
- `topic`: トピック名
- `status`: 🔴 未着手（**ステータスは固定**。学習進捗は手動管理する方針）
- `created`: 今日の日付
- `prerequisites`: 前提となるトピックへの `[[]]` リンクの配列
- `next_steps`: 次に学ぶべきトピックへの `[[]]` リンクの配列
- `difficulty`: beginner | intermediate | advanced
- `estimated_minutes`: 通読目安（分、整数）
- `ai_collaboration`: heavy | partial | minimal（AIに任せやすい度合い）

### 本文セクション

1. **一言で言うと**（blockquote、1文）— マスターファイルの記述を元にした簡潔な要約
2. **3分で全体像** — 以下を埋める:
   - 何を解決する技術か（1行）
   - 代表的な使用シーン（1行）
   - これだけは覚える3つ（箇条書き3項目）
   - AIに任せやすいか（任せやすい / 一部任せられる / 人間判断が要る + 一言根拠）
   - 詰まったらここを読む（関連トピックへの `[[]]` リンク2-3個）
3. **なぜ必要か** — この技術がなかったら何が困るかを具体的に
4. **どの問題を解決するか** — 課題と解決方法を詳細に
5. **他の仕組みとどう関係するか** — 下位/同/上位レイヤーとの関係を `[[]]` 付きで
6. **誤解されやすいポイント** — 実務でよくある勘違い3つ以上
7. **設計のベストプラクティス** — 推奨パターン
8. **AIエージェントとの協働** — 必須セクション。「実装もレビューもAIに任せられる」前提で人間の最終判断を整理する。4サブ節:
   - AIに任せられる部分 / 人間が判断すべき部分（表: タスク種類 / 任せ方（実装/レビュー） / 人間の関与）。**N+1検出・計算量爆発・セキュリティチェックなど従来「人間判断」とされた領域も `/review-ai-code` 経由で AI レビューに任せる**前提で書く。本当に人間判断が要るのは「実データの分布」「ビジネス要件のトレードオフ」「AIレビュー結果の採否」といった文脈依存の判断
   - AI生成コードのレビュー観点（このトピック固有、3項目）
   - 効くプロンプトの型（前提・やってほしいこと・制約・判断基準のテンプレ）
   - AI実装のアンチパターン（表: アンチパターン / なぜ問題か / レビュー観点・対策）
   - 末尾に `→ [[_anti-patterns/_index|AIアンチパターン索引]]` を必ず置く
9. **具体例** — 主要1言語を本文に置く。他言語の追加が必要な場合は `details/` への切り出しを示唆
10. **参考リソース** — 推奨書籍・記事・公式ドキュメント
11. **理解度セルフチェック** — 3問:
    - 1問目: 概念を1分で説明する設問
    - 2問目: 誤解されやすいポイントを Yes/No / 選択で問う設問
    - **3問目: AI生成コードの良し悪しを判断する設問（必須）**
    - Obsidian Callout 形式 `> [!note]- 解答の指針` で折りたたみ解答を必ず添える（`<details>` タグはObsidianでMarkdown解釈されないため使用禁止。Callout内のコードブロックは長くなる場合インラインコードに変換するか省略可）
    - **解答の指針は初学者にも分かるよう、結論だけでなく「なぜそうなるか」の思考プロセスを示す**。専門用語が出る場合は冒頭に `> [!info] 用語ミニ辞典` Callout を置いて補足する
12. **学習メモ** — 空欄

5. ファイルを適切なレイヤーフォルダに保存する
   - ファイル名はスペースなし、英語略語はハイフン区切り
   - Layer4 の場合は `Backend/` または `Frontend/` サブフォルダに配置

## 注意事項

- `[[リンク]]` は実在する（または今後作成予定の）ファイル名と一致させること（Glob で実在確認）
- コード例は最小限かつ実行可能なものにすること（言語明示: ```python, ```typescript 等）
- 図解は Mermaid 記法を使用すること（アスキーアート禁止）
- 日本語で記述し、技術用語は初出時に英語を併記すること
- AI協働章は必須セクション。空欄では送らない
- セルフチェック3問目は必ずAI生成コードレビュー設問にする
- `_index.md` のステータスは更新しない（🔴未着手のまま固定運用）
- 内容は暗記用ではなく「理解のための説明」を心がけること
- **教材は「じっくり何度も読み込むことで効果がある読み物」として設計される**（対象: 初学者〜ミドル → シニア）。手を動かす演習を含めず、読み返したくなる質の高い解説を優先する
