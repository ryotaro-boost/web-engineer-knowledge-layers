# AI実装アンチパターン索引

> **このディレクトリは何か:** AIコーディングエージェントが生成しがちな**過剰設計・誤用・防御過剰**のパターンを、レイヤー別とパターン別の両軸で索引化する場所。各トピック内の「AIエージェントとの協働 → AI実装のアンチパターン」表で言及されたものが、ここに集約される。

## 使い方

- AI生成コードをレビューする際、`/anti-pattern-scan` でコードを渡すとこの索引と照合される（**Week 4 で実装予定**。それまでは `/review-ai-code` で代替できる — トピック観点 + 横断アンチパターンの両方を見る）
- 学習者は **「パターン別」を辿ると、レイヤー横断で「AIが繰り返す癖」を体系的に学べる**
- **「レイヤー別」を辿ると、特定のレイヤー作業時にAIに頻発する罠を一覧できる**

## 横断的なレビュー観点（このディレクトリの整備中も使える）

AI生成コードを受け取ったら、まずこの3つを問う:

### 1. プロジェクトの規約・既存パターンに従っているか
- 既存ユーティリティを使わずに自前実装していないか
- 命名規約・ファイル配置規約から逸脱していないか
- 既存のエラーハンドリング方針（例外 vs Result型）と一致しているか

### 2. 「起こりえないエラーへの対処」を書いていないか
- 内部関数（外部入力を受けない関数）の引数チェック
- 型システムが既に保証している不変条件への `if` チェック
- 意味のないフォールバック値（`?? null`, `|| {}`）
- 握りつぶす `try/catch`

### 3. 要求された機能を「最小限」で実現しているか
- 言われていない機能を足していないか（汎用化・将来拡張のフック等）
- 言われていないインターフェース・抽象化を切っていないか
- 言われていないログ・テレメトリを追加していないか

## 整備方針

各トピックの本文改修（柱3）が進むにつれ、以下の手順で内容が積み上がる:

1. トピック内の「AIエージェントとの協働 → AI実装のアンチパターン」表が更新される
2. その表で初出のパターンが、このディレクトリの**パターン別**ファイルに追記される
3. レイヤー固有のアンチパターンが**レイヤー別**ファイルに集約される
4. `/anti-pattern-scan` skill のナレッジソースとして参照される
