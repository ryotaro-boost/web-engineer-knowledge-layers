> **このファイルは何か:** Layer 0（CS基礎）の **「再読時に1分で思い出すための要約」**。各トピックの要点 + 「AI に頼む前の最低限の備え」を1ページに集約。

## レイヤーの位置

> 計算機の上で「**何ができて何ができないか**」の限界と、効率の良い問題解決手法を知る。
> ここが弱いと上の全レイヤーで「なぜそうなるのか」が理解できず、暗記ベースの開発になる。

## 計算量の感覚 (1秒で計算できるか)

| 計算量 | N=10⁶ で何回 | 直感 |
|---|---|---|
| O(1) | 1 | 一瞬 |
| O(log n) | 約 20 | 一瞬 |
| O(n) | 10⁶ | 一瞬〜数 ms |
| O(n log n) | 約 2×10⁷ | 数十 ms |
| O(n²) | 10¹² | **数十分以上 — 爆発** |
| O(2ⁿ) | 天文学的 | **N=30 でも無理** |

**AIに大量データ処理を任せる前の最低限の備え。**「N が小さいから大丈夫」と AI が言ったら N の上限を必ず確認する。

## ハッシュテーブル要点

- **平均 O(1) のキー検索** — 連想配列・JSオブジェクト・dict・Redis の内部
- **衝突処理** — チェイニング / オープンアドレッシング
- **ハッシュ関数の選択** — 暗号用は SHA-256 / 速度用は xxHash / 等価性のみは内蔵 hash
- **最悪は O(n)** — 悪意のあるキーで衝突を意図的に起こす攻撃 (Hash DoS) がある

詳細: [[ハッシュテーブル]]

## 並行性の3大プリミティブ

| 概念 | 何が問題か | 防ぎ方 |
|---|---|---|
| **競合状態** | 複数処理が同データに同時アクセスし、順序で結果が変わる | アトミック操作 / ロック / トランザクション |
| **デッドロック** | 相互にロック解放を待ち合って永久停止 | ロック取得順序を統一 |
| **ライブロック** | 互いに譲り合って進まない | リトライにジッター追加 |

## AI協働でよく出るアンチパターン (Layer 0)

- **計算量を考えずに「とりあえず動く」コード** → ループ内ループ、ネスト Object.keys、List.find のループ
- **ハッシュとツリーを混同** — Set / Map と SortedSet / SortedMap の違い
- **競合状態を「なんとなく lock で囲んで終わり」** → 範囲が広すぎてパフォーマンス激減
- **アルゴリズムの再発明** — 標準ライブラリの sort / binary search を使わずに自前実装

詳細: [[_anti-patterns/レイヤー別/Layer0|Layer 0 アンチパターン集]]
