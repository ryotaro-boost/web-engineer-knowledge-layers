# 週次プラン — 第1〜4週で「最小学習パス」を回す

> **このファイルは何か:** [[_starter/00_最小学習パス|14トピックの最小学習パス]] を **4週間**の枠で順に通読・再読するための具体的な週次タスク。一度で覚えようとせず、**「週ごとに通読 → 翌週に薄く再読」** のリズムで定着させる。

## 設計思想

- 本教材は **じっくり何度も読み込むことで効果がある読み物**。1度で全部覚えなくてよい
- **「初読 → 1週後の再読 → 1ヶ月後の再読」** で、読むたびに違う層が見える
- 平日30分×5日 + 週末1時間で、**週あたり3.5時間**程度の負荷を想定する
- 各週末に **「通読したトピックのセルフチェック3問」** を解く。3問目（AI生成コードレビュー設問）に答えられない時は本文に戻る
- **AI出力が浅く感じたら、それは自分の判断軸が育っているサイン**。先週の自分なら気づかなかったことに気づけるか観察する

## 週次プランの俯瞰

| 週 | テーマ | 通読する新トピック | 再読する前週トピック |
|---|---|---|---|
| 第1週 | Webの最低限 | 4トピック (Phase 1) | — |
| 第2週 | データの基本 | 3トピック (Phase 2) | 第1週の4トピックを薄く |
| 第3週 | 並行と防御 | 3トピック (Phase 3-4) | 第2週の3トピックを薄く + Phase 1から1つ深掘り |
| 第4週 | 設計と運用 | 4トピック (Phase 5-6) | 第3週の3トピックを薄く + 全14トピックの「3分で全体像」だけ拾い直し |

## 第1週: Webの最低限を骨格で掴む

> 「リクエストがどこを通るか」を頭に入れる週。まだ深く理解する必要はない。**「ここに何かあったな」というインデックス**を作る。

### Day 1-2: [[HTTP-HTTPS]]
- 本文を通読。特に **「ステートレス性」** がなぜ後続のCookie/セッション/CSRFの存在理由になるかを意識する
- 詰まったら [[_starter/03_AIコーディング時代の学び方]] の前提認識に戻る

### Day 3: [[ルーティングとミドルウェア]]
- 「URLとビジネスロジックの対応付け」だけ理解できれば十分。ミドルウェアは「共通処理をDRYにする仕組み」と覚える

### Day 4: [[DOMと仮想DOM]]
- 「画面が更新される」の中身。ReactやVueがなぜ存在するのかの根本だけ押さえる

### Day 5: [[認証と認可]]
- **認証 ≠ 認可** の区別が最重要。混同するとセキュリティホールになる理由を [[_anti-patterns/レイヤー別/Layer4-Backend]] で確認する

### 週末: セルフチェック
- 上記4トピックの **「理解度セルフチェック」3問** をすべて解く
- 答えられなかった問題は本文に戻る。**3問目（AI生成コードレビュー設問）が答えられない場合は最重要**。次週の再読で必ず再挑戦する

## 第2週: データの基本

> 「データはどう保存・取得されるか」の骨格。**O記法 → ハッシュテーブル**の順で進めると、「なぜ O(1) で見つかるのか」が地続きで腑に落ちる。

### Day 1-2: [[トランザクション]]
- ACID特性が **「途中で失敗しても壊れない」保証** であることを理解
- 認証で扱った「同時に複数ユーザがログインしたら？」と接続して読むと立体的になる

### Day 3: [[計算量-BigO]]
- N=100万のときに何が起きるかを必ず手で書いて確認。**AIに大量データ処理を任せる前の最低限の備え**

### Day 4: [[ハッシュテーブル]]
- 計算量の知識を **具体的なデータ構造で実感する週**。連想配列・JSオブジェクト・dict・Redisの内部すべてこれ

### Day 5: 再読日 — 第1週の4トピック
- 各トピックの **「3分で全体像」と「誤解されやすいポイント」だけ** 読み直す
- 再読では「先週気づかなかった行」を 1〜2 つ見つけることがゴール

### 週末: セルフチェック
- Phase 2 の3トピック分を解く
- 第1週の4トピックの3問目だけ再挑戦（答え合わせのみ、間違えても本文への深い再読は来週）

## 第3週: 並行と防御 — 「同時に動く」と「外部入力は信用しない」

> 実務で最も事故が多い領域。**ここで一度詰まる**ことが、後の理解の起点になる。

### Day 1-2: [[並行性の基本概念]]
- 競合状態とデッドロックを **「2つの関数が同じデータを触ったら何が起きるか」** で考える
- トランザクション・非同期処理・スレッドプールの全ての根本

### Day 3: [[SQLインジェクション]]
- **プリペアドステートメント**で根本解決する原理。「拒否リスト思考」がなぜ穴だらけかを [[_anti-patterns/パターン別/拒否リスト思考|拒否リスト思考]]（Week 11以降整備予定）の発想で理解
- 詰まったら [[Layer3-データ永続化/RDB|RDB]] の SQL 実行モデルに戻る

### Day 4: [[CSRF]]
- 「ブラウザがCookieを自動送信する」性質を悪用する攻撃。SameSite と CSRFトークンの組み合わせで防ぐ
- XSS と並んで「**Webアプリ独自の攻撃**」の代表

### Day 5: 再読日 — 第2週の3トピック + Phase 1 から1つ深掘り
- 第2週の3トピックは「3分で全体像」のみ
- Phase 1 から **「先週よく分からなかった1トピックを選んで本文を再読」** する

### 週末: セルフチェック
- Phase 3-4 の3トピックを解く
- 並行性 + SQLi + CSRF はすべて「**外部入力 / 競合 / セキュリティ**」の根に繋がる。3問目（AI生成コードレビュー）でこの繋がりが見えるか確認

## 第4週: 設計と運用 — 「変更しやすさ」と「動いた後」

> ここまでで Web の基礎は揃っている。第4週は **「コードを書ける段階から、システム全体を設計・運用できる段階へ」** の橋渡し。

### Day 1: [[関心の分離]]
- 全設計原則の根本。「**変更の理由が異なるものは分離する**」を念仏のように繰り返す
- 「どこから手を付けるか」の根本判断軸

### Day 2: [[SOLID原則]]
- 関心の分離を5つの観点に分解したもの。特に **DIP** がテスタビリティに直結することを理解
- AI に「インターフェースを切れ」と頼むと過剰になりがち。AIコードレビュー観点で確認する練習をする

### Day 3: [[モニタリング]]
- 「**見えないものは直せない**」。メトリクス・ログ・トレースの3本柱
- 第3週の SQLインジェクション・CSRF と接続: **「攻撃を受けたか」を観測する手段** がここ

### Day 4: [[CI-CD]]
- 「**手動デプロイが怖い**」を解決する。小さく頻繁にリリースしてリスクを下げる原理
- DevOps文化の入口

### Day 5: 再読日 — 全14トピックの「3分で全体像」だけ拾い直し
- 1日で全14トピックの「3分で全体像」セクションだけを読む。**所要時間 約1時間**
- このタイミングで [[_graph/依存グラフ|依存グラフ]] を眺めると、各トピックの位置関係が立体的に見える

### 週末: 総まとめ
- 第4週の4トピック分のセルフチェックを解く
- **3問目（AI生成コードレビュー設問）を全14トピック分振り返り、「答え方が変わったもの」を見つける** — 4週間の成長指標
- 次に進むなら [[_starter/02_実務症状からの逆引き|実務症状からの逆引き]] へ

## 第5週以降の選択肢

4週間で14トピック × 3問 = 42問の自己問答を回した後の選択肢:

| 進む方向 | 推奨度 | 理由 |
|---|---|---|
| 各レイヤーの`_index`を順に通読（Layer 0 → 7） | ★★★ | 全体俯瞰の解像度が上がる。各レイヤーの未習トピック（66 - 14 = 52トピック）を順に拾える |
| 興味のあるレイヤーをまず1つ深掘り | ★★ | フロントエンド志望なら Layer 4 Frontend → Layer 5 へ。バックエンド志望なら Layer 3 → Layer 4 Backend → Layer 6 へ |
| [[_starter/02_実務症状からの逆引き]] を辞書のように使う | ★★ | 実務で詰まる時に該当レイヤーへ降りる「逆引き」運用。再読の動機付けになる |
| 同じ14トピックを再度通読 | ★ | 1ヶ月後の再読は **「見える層が変わる」** ので有意義。ただし新規習得は止まる |

## このプランをパーソナライズする

`/starter-path` skill を使うと、現在のスキル状況に応じてこの週次プランを **個別に調整** できる:

- すでに HTTP / 認証認可は分かっている人 → **第1週をスキップして第2週から開始**
- 並行性が苦手という自覚がある人 → **第3週を 2 週間に分割**
- フロントエンドのみ触る人 → SQLi / CSRF を圧縮し、**Layer 4 Frontend へ早期に展開**
